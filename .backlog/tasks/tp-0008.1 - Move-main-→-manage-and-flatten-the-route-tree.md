## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Structural rename and flatten. Move src/routes/main → src/routes/manage and collapse the two layers of nesting (dashboard/ and inner dashboard/manage/) so each manage section sits directly under /manage/. Update every reference. Delete player routes that don't belong in an admin manage area.

Target structure:
  manage/
    +layout.svelte        (current main/+layout.svelte)
    +layout.server.ts     (NEW — admin auth guard; redirects to /manage/login if not admin)
    +page.svelte
    login/
      +page.svelte        (current main/login/+page.svelte — form action updated to /manage/login)
      +page.server.ts     (current main/login/+page.server.ts — redirects to /manage on success)
      register/
        +page.svelte      (current main/login/register/+page.svelte — updated links)
        +page.server.ts   (current main/login/register/+page.server.ts)
    users/
    characters/
    events/
    sessions/
    skills/
    items/
    implants/

Moves:
- main/+layout.svelte → manage/+layout.svelte
- main/+page.svelte → manage/+page.svelte
- main/login/** → manage/login/** (KEEP — admin login; update form action and internal hrefs from /main/login → /manage/login)
- main/dashboard/+layout.svelte → merge into manage/+layout.svelte or drop (its only role is a gray-background wrapper)
- main/dashboard/users/** → manage/users/**
- main/dashboard/characters/** → manage/characters/** (KEEP only the admin-facing parts; player /api/my flow is removed in sibling tasks)
- main/dashboard/sessions/** → manage/sessions/**
- main/dashboard/manage/skills/** → manage/skills/**
- main/dashboard/manage/items/** → manage/items/**
- main/dashboard/manage/implants/** → manage/implants/**
- main/dashboard/manage/events/** → manage/events/**

New file — manage/+layout.server.ts (admin auth guard):
- Read the session token from cookies
- Call /api/authentication (or check Session_Roles) to verify the session has the `admin` role
- If not authenticated or not admin: redirect(302, '/manage/login')
- The /manage/login route itself must be exempt from this guard (it is a sibling, not a child, so the layout guard does not apply to it automatically — use a condition on the path or keep login outside the guarded layout)

Note: the login page is exempt because it sits inside manage/ but the guard must NOT redirect /manage/login itself (infinite loop). Implement the guard to skip redirect when `url.pathname === '/manage/login'` or `/manage/login/register`.

Deletes (player-facing, do not belong in admin manage):
- main/dashboard/events/+page.svelte and +page.server.ts (player list — calls /api/events/open) — the admin events list comes from main/dashboard/manage/events/ moved up to /manage/events
- main/dashboard/events/[eventId]/** (player sign-up flow)

Reference updates required (grep shows current /main/* usage):
- src/lib/components/navigation.svelte (8 links to /main/...)
- src/lib/codex/components/login-window.svelte (2 references to /main/login and /main/login/register) — repoint at /manage/login and /manage/login/register
- Any internal href='.' inside moved pages keeps working since it's relative
- Form action in login page: action='/main/login' → action='/manage/login'
- Internal link to register: href='/main/login/register' → href='/manage/login/register'

No behavior changes beyond pathing and the new auth guard in this task. Per-section API/auth fixes live in sibling tasks (TP-8.2 .. TP-8.6).
