## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Rewire the users management section to go through /api/users and /api/users/[id], and harden those endpoints with admin authGuard.

Current state (paths post-rename):
- /manage/users/+page.server.ts imports userRepo directly and calls userRepo.getAll() — must use fetch('/api/users') instead
- /manage/users/[id]/+page.server.ts imports userRepo and calls userRepo.getById() — must use fetch('/api/users/[id]')
- /manage/users/[id]/+page.svelte already POSTs to /api/users/[id] — keep as-is, but the API endpoint must verify admin

API endpoints to harden (src/routes/api/users/):
- GET /api/users — already admin-guarded; verify it still is after refactor
- GET /api/users/[id] — currently public, add authGuard(getSessionToken(cookies), ['admin'])
- POST /api/users/[id] — currently public, add authGuard(getSessionToken(cookies), ['admin'])

Body shape note: the API CLAUDE.md documents POST /api/users/[id] body as { user: User }, but the current handler destructures { user } from the parsed body — meanwhile the [id]/+page.svelte sends raw `user` (JSON.stringify(user)) which means the handler currently sees `user === undefined`. Reconcile: either change the handler to accept the raw user object, or change the page to send { user }. Document the chosen shape in api/CLAUDE.md.

Reference: src/lib/utils/request.ts authGuard signature.
<!-- SECTION:DESCRIPTION:END -->
