## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Rewire the characters management section to use the admin-scoped /api/characters endpoints (not /api/my/...) and ensure those endpoints accept admin auth.

Current state (paths post-rename):
- /manage/characters/+page.ts calls /api/my/characters (current-user scoped) — must call /api/characters (admin-scoped: lists all characters across users)
- /manage/characters/[id]/+page.server.ts imports characterRepo and calls characterRepo.getById() directly — must call fetch('/api/characters/[characterId]')
- /manage/characters/[id]/+page.server.ts also calls userRepo.getAll() directly for the owner dropdown — must call fetch('/api/users')
- /manage/characters/new/+page.server.ts calls userRepo.getAll() directly — must call fetch('/api/users')
- /manage/characters/[id]/+page.svelte POSTs to /api/characters/[characterId] — keep, but endpoint must accept admin
- /manage/characters/new/+page.svelte PUTs to /api/characters — keep

API endpoint changes (src/routes/api/characters/):
- GET /api/characters — already authGuard(['admin']); ok
- PUT /api/characters — currently authGuard(['user']); admin must be able to create characters from the manage panel. Add 'admin' (['admin', 'user']) — verify codex new-character flow still works under 'user'
- GET /api/characters/[characterId] — currently authGuardForUser(['user']); allow ['admin', 'user'] so admin can view any character
- POST /api/characters/[characterId] — same: allow ['admin', 'user']

IMPORTANT: do not break the player character flows that legitimately use /api/characters/[characterId] under ['user']. Verify callers in src/lib/codex/** and src/routes/api/my/** before tightening roles further.
<!-- SECTION:DESCRIPTION:END -->
