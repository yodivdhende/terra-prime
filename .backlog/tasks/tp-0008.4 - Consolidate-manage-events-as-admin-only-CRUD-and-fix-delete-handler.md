## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Consolidate event management into a single admin-only /manage/events section, remove the duplicate player views, and ensure all mutations go through /api/events with admin authGuard.

Current state (pre-rename has two competing event trees):
- main/dashboard/events/ — player list, calls /api/events/open (DELETE in TP-8.1)
- main/dashboard/events/[eventId]/ — player sign-up flow (DELETE in TP-8.1)
- main/dashboard/manage/events/ — admin list, calls /api/events (this is what survives, moved to /manage/events in TP-8.1)
- main/dashboard/manage/events/new/+page.svelte — PUTs /api/events; no server load needed
- main/dashboard/manage/events/[id]/ — admin edit; calls fetch via /api/events/[eventId]

Work in this task (after TP-8.1 has moved files):
- Verify /manage/events/+page.server.ts uses fetch('/api/events') only (no eventRepo import)
- Verify /manage/events/[id]/+page.server.ts uses fetch('/api/events/[eventId]') only (no eventRepo import) — currently already does
- Verify the create form uses PUT /api/events and the edit form uses POST /api/events/[id] and DELETE /api/events/[id]
- API endpoints (src/routes/api/events/):
  - GET /api/events — currently authGuardForUser(['admin']); ok
  - PUT /api/events — currently authGuard(['admin']); ok
  - GET /api/events/[eventId] — currently authGuardForUser(['admin','user']); leave (open to user for sign-up elsewhere)
  - POST /api/events/[eventId] — currently authGuard(['admin']); ok
  - DELETE /api/events/[eventId] — currently authGuard(['admin']); ok BUT the handler reads params.id and the route param is named eventId — fix to params.eventId, otherwise delete is broken
- LarpEvent body coercion (start/end as Date) is already handled — keep
