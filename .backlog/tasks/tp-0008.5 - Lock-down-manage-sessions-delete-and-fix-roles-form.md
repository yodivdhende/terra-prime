## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Harden the sessions admin area: lock down the delete endpoint with admin authGuard and fix the create-session form action.

Current state (paths post-rename, /manage/sessions/):
- /manage/sessions/+page.server.ts fetches /api/sessions (admin-guarded) and reads the current session cookie — keep
- /manage/sessions/+page.svelte calls fetch('/api/sessions/[token]', { method: 'DELETE' }) — keep
- /manage/sessions/new/+page.server.ts has a form action that POSTs to /api/sessions with body { description, end: null, roles: [roles] } — the `roles` form field is a multi-select but formData.get('roles') returns only the first value, then it's wrapped in an extra array. Use formData.getAll('roles') to get all selected values

API endpoints (src/routes/api/sessions/):
- GET /api/sessions — currently admin-guarded; ok
- POST /api/sessions — verify admin-guarded
- DELETE /api/sessions/[token] — currently has NO authGuard at all; add authGuard(getSessionToken(cookies), ['admin'])

Edge case: when an admin deletes their own session token they will be logged out — acceptable, but document the behavior in the page or confirm before delete.
<!-- SECTION:DESCRIPTION:END -->
