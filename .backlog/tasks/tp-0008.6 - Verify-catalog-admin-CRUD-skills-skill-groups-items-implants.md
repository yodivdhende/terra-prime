## Description

Verify the catalog admin sections (skills, skill groups, items, implants) are complete and properly admin-guarded. These are mostly working today; this task fills in gaps and confirms the contract.

Sections (paths post-rename):
- /manage/skills/ + /manage/skills/new/ + /manage/skills/[id]/
- /manage/skills/groups/ + /manage/skills/groups/new/ + /manage/skills/groups/[id]/
- /manage/items/ + /manage/items/new/ + /manage/items/[id]/
- /manage/implants/ + /manage/implants/new/ + /manage/implants/[id]/

Per section, verify:
- List page: loads via fetch('/api/<section>'), shows a + add link and a row per record with link to /[id]
- Detail page: loads via fetch('/api/<section>/[id]'), has save (POST) and delete (DELETE) buttons; on success goto('.')
- New page: PUTs to /api/<section>; no server load needed (or only loads dependent dropdowns via fetch, like skill groups for skills/new)

Gaps to address:
- /manage/skills/new/+page.server.ts loads skill groups via skillRepo.getAllGroups() directly — must use fetch('/api/skills/groups') instead (currently in main/dashboard/manage/skills/[id]/+page.server.ts; verify the new/ page does the same after the move)
- Confirm all detail pages have delete buttons (skills/[id] yes, items/[id] yes, implants/[id] yes, skills/groups/[id] yes)
- Confirm all list pages have a CirclePlus "add" link (verify items, implants, events — they all do)

API endpoint audit (src/routes/api/{skills,items,implants}/):
- All list GETs are authGuard(['admin', 'user']) — that's fine for shop reads but verify no admin-only field leaks
- All PUT/POST/DELETE are authGuard(['admin']) — verify
- /api/skills/groups, /api/skills/groups/[id] — verify authGuard(['admin']) on mutating verbs

No structural changes to these sections, just verification and the small repo→API swap on any remaining server loads.
