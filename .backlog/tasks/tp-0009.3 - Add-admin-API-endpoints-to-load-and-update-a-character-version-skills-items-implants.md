## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The admin flow needs to load a character + all its versions (with full skills/items/implants) and persist changes back. Today's character version writes go through /api/my/characters/versions which is player-scoped (uses session user). Add or extend admin-authed endpoints under /api/characters/[id]/versions and /api/characters/[id]/versions/[versionId] returning/accepting CharacterVersionFull. Reuse the existing repo/service code where possible — schema columns are in Character_Version_{Skills,Items,Implants} per site/CLAUDE.md.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 GET /api/characters/[id]/versions returns the list of versions for that character (id, name) — admin only
- [ ] #2 GET /api/characters/[id]/versions/[versionId] returns a CharacterVersionFull (skills/items/implants populated) — admin only
- [ ] #3 POST (or PUT) /api/characters/[id]/versions/[versionId] persists a CharacterVersionFull payload (replaces skills/items/implants for that version) — admin only
- [ ] #4 Endpoints reuse the type CharacterVersionFull from src/routes/api/my/characters/versions/+server (re-export if needed)
- [ ] #5 Endpoints are guarded by authGuard with the admin role (matches the pattern set in TP-0008.3)
<!-- AC:END -->
