## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In the register flow the budget comes from the selected event (event.budget). The admin editor isn't scoped to an event, so we need a deliberate decision before wiring the shared component (TP-0009.1). Pick one approach, document the choice in this task, then implement: (a) no budget cap — pass budget=0 so the budget UI hides and remaining stays Infinity-equivalent; (b) admin picks a reference event from a dropdown to drive the budget; (c) admin types a budget number manually. (a) is the lowest friction and matches 'admin can do anything' framing — consider it the default unless the user wants enforced budgets in admin mode.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Decision is captured in this task's notes (which option, why)
- [ ] #2 Shared component (TP-0009.1) supports the chosen mode — if (a), budget=0 hides the budget bar and the over-budget block; if (b)/(c), admin UI feeds budget number into the component
- [ ] #3 Admin can still see spent totals per tab even when no budget cap applies
<!-- AC:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Chose option (a): no budget cap in admin mode. character-version-shop passes Infinity as shopRemaining when budget=0, blocking no buy buttons. CharacterCreateNav hides budget section when budget=0.
