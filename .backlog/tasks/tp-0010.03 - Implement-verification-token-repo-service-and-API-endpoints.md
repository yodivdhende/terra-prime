## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Token storage + verification flow.

Files to create:
- src/lib/db/email_verification.repo.ts — createToken(userId): uuidv4 + insert with ExpiresAt = NOW() + INTERVAL 24 HOUR; deletes prior tokens for the same user first. consumeToken(token): verify exists + not expired, UPDATE Users SET Verified=1, DELETE token, all in one transaction; throws RequestError(400,'invalid or expired') otherwise; returns userId. removeExpired() called at top of createToken (mirrors session.repo.ts:114).
- src/lib/server/verification.service.ts — sendVerificationEmail(userId, email): create token, build link `${PUBLIC_BASE_URL}/verify-email?token=${token}`, call emailService.sendTemplated({to:email, templateKey:'verify_email', link}). confirmToken(token): thin wrapper around repo.consumeToken.
- src/routes/api/authentication/verify-email/+server.ts — POST, public. Body {token}. Calls confirmToken. Returns {ok, userId}.
- src/routes/api/authentication/verify-email/resend/+server.ts — POST, user. authGuardForUser, fetch user, error if already verified, call sendVerificationEmail (awaited so caller sees errors), return {ok}.
- src/routes/api/admin/emails/send/+server.ts — POST, admin. Body {to, templateKey, link?}. authGuard for admin. Calls emailService.sendTemplated. Returns {ok}.

Also modify src/lib/db/user.repo.ts: add Verified to userSelector, add verified:boolean to User type and isUser guard (cast MySQL TINYINT to Boolean), update all three User-returning queries to include verified.

Env var: PUBLIC_BASE_URL.
