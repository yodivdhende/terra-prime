## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Backend CRUD endpoints for email templates.

Create API endpoints (mirror /api/items pattern):
- src/routes/api/email-templates/+server.ts — GET (admin) returns EmailTemplate[]; PUT (admin) upserts, returns {id}
- src/routes/api/email-templates/[id]/+server.ts — GET (admin) returns one; POST (admin) updates; DELETE (admin) removes

All endpoints use handleRequest() + authGuard for admin role.

The admin manage UI that consumes these endpoints is tracked separately in TP-0010.07.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Created /api/email-templates/+server.ts (GET admin → EmailTemplate[]; PUT admin upserts via repo.save, returns {id}) and /api/email-templates/[id]/+server.ts (GET admin, POST admin update, DELETE admin). All use handleRequest + authGuard with admin role. Integration-tested against the running dev server: admin sees the seeded verify_email row, user gets 403 on GET, PUT creates a row (returns new id), GET single roundtrips, POST update reflects in subsequent GET, DELETE removes the row (404 on re-fetch), non-admin POST returns 403. Uses isEmailTemplate body validation throwing BadRequest.
