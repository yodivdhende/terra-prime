## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Frontend admin pages to manage email template { key, docUrl } rows. Consumes the API endpoints from TP-0010.05.

Files to create (mirror the /manage/items pattern):
- src/lib/components/email-template-form.svelte — shared form. bind:template. Inputs:
    - Key: text input, required, lowercase + underscores. Disabled when editing an existing template (preserves getByKey lookups).
    - DocUrl: text input, required, with an 'Open doc' link/button that opens the URL in a new tab so admins can verify it.
    - Optional read-only line showing the resolved hardcoded subject if the key matches a known one in email.service.ts SUBJECTS.
- src/routes/manage/emails/+page.server.ts — loads via fetch('/api/email-templates') → { templates: EmailTemplate[] }
- src/routes/manage/emails/+page.svelte — table { Id, Key, DocUrl (truncated, linked) }; CirclePlus icon link to emails/new; rows link to emails/[id]
- src/routes/manage/emails/new/+page.svelte — empty form, PUTs to /api/email-templates on save, goto('.') on success
- src/routes/manage/emails/[id]/+page.server.ts — loads one template via fetch('/api/email-templates/[id]')
- src/routes/manage/emails/[id]/+page.svelte — form + Save (POST /api/email-templates/[id]) + Delete (DELETE /api/email-templates/[id]) buttons

Modify src/routes/manage/+page.svelte to add a nav link to /manage/emails so admins can find the new section.

Admin-only is enforced by the existing /manage/+layout.server.ts redirect.
