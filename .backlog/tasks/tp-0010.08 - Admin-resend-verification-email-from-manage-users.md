## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Backend endpoint that lets admins trigger a verification email resend for a *specific* user (not just self-resend).

Create src/routes/api/admin/users/[id]/resend-verification/+server.ts:
- POST, admin-only via authGuard.
- Loads target user via userRepo.getById({id}). 400 if user not found.
- 400 if user.verified is true.
- Calls verificationService.sendVerificationEmail(userId, user.email).
- Returns json({ok: true}).

Rationale: the existing /api/authentication/verify-email/resend operates on the current session user. The admin path is a different authorization model, so it lives in /api/admin/.

The /manage/users page consumer of this endpoint is tracked separately in TP-0010.09.

POST, admin-only via authGuard, isNumberOrError on params.id, loads target user via userRepo.getById, throws RequestError(400) if already verified, awaits sendVerificationEmail(userId, user.email), returns {ok:true}. Integration-tested: 400 'email is already verified' for verified user, 403 'not autherized' for non-admin caller, and for unverified target the token row IS created (proving verification.service.sendVerificationEmail runs through createToken) — the upstream Gmail call then fails 500 with 'File not found: REPLACE_ME.' because the seeded Doc URL is still a placeholder. That surface-through-to-admin behavior is intentional: the admin will see real Gmail/Doc setup problems instead of a fake 200.
