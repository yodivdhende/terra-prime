## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Surface email verification state in the admin users area and let admins act on it.

Modify src/routes/manage/users/+page.svelte (list page):
- Add a 'Verified' column to the existing table (after Email). Render a clear yes/no indicator per row (e.g. a check icon or plain 'yes' / 'no').
- Source: the existing /api/users endpoint will return the new 'verified' boolean once TP-0010.03 lands.

Modify src/routes/manage/users/[id]/+page.svelte (detail page):
- Show the current verification status (e.g. 'Verified ✓' / 'Not verified').
- When not verified: add a 'Resend verification email' button that POSTs to /api/admin/users/{id}/resend-verification (the endpoint from TP-0010.08), then shows clear success/failure feedback inline.
- When already verified: do not show an active button (either hide it or show a disabled state explaining no action is needed).
- Slot the new controls below the existing name/email inputs (manage/users/[id]/+page.svelte:30-35).

Out of scope:
- A manual 'mark as verified' admin override (could be a follow-up).
- Sorting/filtering by verified state on the list page.

Depends on TP-0010.03 (adds 'verified' to User type / /api/users response) and TP-0010.08 (admin resend endpoint).
