## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
API endpoints. Pattern mirrors verify-email + admin resend-verification (see src/routes/api/authentication/verify-email and src/routes/api/admin/users/[id]/resend-verification).

Files to create:
- src/routes/api/authentication/forgot-password/+server.ts — POST, public. Body {email}. Look up user by email; if found, sendPasswordResetEmail in fire-and-forget; ALWAYS return {ok:true}. Never reveal whether an email is registered (anti-enumeration).
- src/routes/api/authentication/reset-password/+server.ts — POST, public. Body {token, password}. Validate non-empty token + password. Call passwordResetService.resetPasswordWithToken. Returns {ok:true, userId} on success, 400 for invalid/expired token or weak password.
- src/routes/api/admin/users/[id]/send-password-reset/+server.ts — POST, admin via authGuard. isNumberOrError(params.id). Load user, await sendPasswordResetEmail, return {ok:true}.

Use handleRequest + getSessionToken patterns from existing endpoints. Routes use RequestError for 4xx.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 POST /api/authentication/forgot-password returns {ok:true} for both known and unknown emails (no enumeration)
- [ ] #2 POST /api/authentication/forgot-password triggers a reset email when the email matches an existing user
- [ ] #3 POST /api/authentication/reset-password consumes a valid token and persists the new password; user can subsequently log in with it
- [ ] #4 POST /api/authentication/reset-password returns 400 for invalid/expired tokens
- [ ] #5 POST /api/admin/users/[id]/send-password-reset requires admin role and triggers a reset email for the target user
