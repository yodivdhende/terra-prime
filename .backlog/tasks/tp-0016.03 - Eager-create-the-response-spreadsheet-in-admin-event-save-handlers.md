## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Wire admin event saves so that the moment an event with a FormId lacks a SheetId, the server creates the linked spreadsheet and stores its ID. This way admins see the destination spreadsheet in Drive immediately, not on the first registration.

Files:
- `site/src/lib/server/event-sheet.service.ts` (new)
  - `buildHeaders(form: GoogleForm): string[]` — `['Timestamp', 'User ID', 'Name', 'Email', ...questionTitles]`. Walks `form.items[*]` like `buildEntryIdMap` (lines 49–57 of `google-form-service.ts`): one entry per `questionItem.question`, expanded for `questionGroupItem.questions[]` using `rowQuestion.title`.
  - `questionsInOrder(form: GoogleForm): { questionId: string; title: string }[]` — same shape, exported for the submit endpoint
  - `ensureSpreadsheetForEvent(event): Promise<string>` — fetches form via `getGoogleFormService().getForm`, builds headers, calls `getGoogleSheetService().createResponseSpreadsheet(\`\${event.name} — Registrations\`, '1fxhnT9gEr6CWyfBgGQ1ZWYoGkpLH4c-J', headers)`
- `site/src/routes/api/events/[eventId]/+server.ts` (POST): after `eventRepo.save(event)`, re-read it; if `formId && !sheetId`, call `ensureSpreadsheetForEvent` and `eventRepo.setSheetId`. Swallow + log failures so a Drive hiccup doesn't 500 the admin save.
- `site/src/routes/api/events/+server.ts` (PUT): same logic after insert using `insertId`.

The submit endpoint will keep a lazy-create safety net for events whose eager-create attempt failed.
<!-- SECTION:DESCRIPTION:END -->
