## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace the Node `ws` server with a tiny **link-only** MQTT coordinator. It does NOT aggregate
or rebroadcast status — that is now peer-to-peer (browser aggregates) — so its sole job is the
time-windowed link rendezvous.

### Files
- Rename `site/websocket-server/` → `site/mqtt-server/`.
- **`site/mqtt-server/connection-coordinator.ts`** (was `connection-socket.ts`):
  - Keep ALL exported types (`ConnectionCommand`, `StatusCommandInfo`, `WebStatusCommandInfo`,
    `CYDStatusCommandInfo`, `Screen`, `Screens`, `Command`) — the frontend imports them.
  - Replace the `ws` class with an `mqtt` client: `connect(process.env.MQTT_URL ?? 'mqtt://localhost:1883')`,
    subscribe **only** `terra/link`.
  - On a `terra/link` message, run the existing `handleLink` logic verbatim — the `links: Map<string, Date>`,
    the `isLinked === false` early return, the first-seen → `loading` branch, and the
    `> 3000 && < 4800` window → `loot` branch — but emit with
    `client.publish('terra/goto/' + origin, JSON.stringify({ screen }))` instead of `webSocket.send`.
- **`site/mqtt-server/index.ts`**: remove `WebSocketMidiator`; keep `app.use(handler)` +
  `app.listen(port)` for SvelteKit, and start the coordinator.
- **Delete `site/mqtt-server/socket-server.ts`** (HTTP-upgrade routing no longer needed).
- **`site/package.json`**: add `"mqtt": "^5"`, remove `"ws"` and `"@types/ws"`; rename script
  `start:websocket` → `start:mqtt` running `node ./mqtt-server`.

Note: the frontend type import path is updated in TP-0019.03.
