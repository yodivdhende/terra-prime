## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Move the admin sessions page off the raw browser `WebSocket` onto MQTT.js over the broker's
WebSocket listener, and aggregate connection status client-side from retained topics.

### File: `site/src/routes/manage/sessions/+page.svelte`
- Import `mqtt` and connect with
  `mqtt.connectAsync(env.PUBLIC_MQTT_WS_URL ?? 'ws://localhost:9001', { will: { topic: 'terra/status/' + sessionToken, payload: '', retain: true } })`.
- On connect: publish own retained status to `terra/status/{sessionToken}`
  (`{ sessionToken, connectionType: 'Web' }`), then **subscribe `terra/status/+`**.
- Maintain `connections` as a token-keyed reactive map (e.g. `SvelteMap` from `svelte/reactivity`).
  On each message, parse the token from the topic: empty payload → delete that token;
  non-empty → `JSON.parse` and set. Iterate the map's values in the template (`SessionRow`
  consumes the same `StatusCommandInfo` shape via `connections.find(...)`, so adapt to map values).
- `sendCommand('virus', token)` → `client.publish('terra/goto/' + token, JSON.stringify({ screen: 'virus' }))`.
- Update the type import to `../../../../../mqtt-server/connection-coordinator`.
- Use `PUBLIC_MQTT_WS_URL` via SvelteKit's `$env/dynamic/public` (or `$env/static/public`),
  defaulting to `ws://localhost:9001`. Add it to `.env.example` / README if present.

This removes the dependency on the SvelteKit server for realtime and resolves the old
5173/3000 port mismatch.
